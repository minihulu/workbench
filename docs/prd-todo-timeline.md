### 1.1 原始需求复述

用户原话整理（"先做出来不对再改"）：

1. **布局改为矩阵式**：大任务一**行**一行列出；每行右侧以**横向"列"**排出该大任务的多个小任务卡片。取代当前看板（看板 = 大任务整列、子任务竖向卡片）。
2. **小任务显示模式切换**：每个小任务单元可切换「无截止日期」或「倒数日期」（如"剩 12 天"）。
3. **今日聚焦改版（重点）**：不再用星标/收藏决定，改为 **只要某小任务的时间线（起日期~止日期）覆盖"今天"，它今天就进今日聚焦**；今日聚焦**只显示任务名**、**带「完成」按钮**；时间线内**每一天 = 一次完成机会**（如 8/1~10/31 约 92 天 → 92 天里每天出现、每天可完成 1 次）。完成按钮具体交互待定（用户说"看我后面怎么解释"），PRD 暂按"点击=标记今天这次完成"描述并标注待细化。
4. **完成记录 + 日历**：每次"完成"按「小任务 + 日期」单独存一条记录；模块下方建立**日历**，点某天 → 跳转到"当天完成的所有任务"视图。

> 数据结构语义红线：`directions`（大任务/方向）与 `notes`（小任务/笔记，`dir` 外键指向 direction）的父子关系**不可破坏**，旧数据必须兼容。

## 2. 产品目标（Product Goals）

本次重设计要解决的核心问题：**让"带有起止时间线的任务"能够按天持续推进、并且可追溯每一天做了什么。** 当前看板只按"大任务分列 + 子任务卡片"组织，既看不出每个小任务在日历维度上的推进节奏，也无法把"今天该推进什么"与"每天打一次卡"闭环起来。矩阵式布局让每个大任务下的小任务一目了然、横向可扫；时间线驱动的今日聚焦把"今天该推进哪些小任务"自动算出来；每日完成记录 + 日历回看则把"每天是否推进、推进了什么"固化成可追溯的历史。一句话：**把待办从"列清单"升级为"按天打卡、按天复盘"的推进系统。**

| # | 目标 | 衡量方式 |
|---|---|---|
| G1 | **矩阵式一眼看清**：大任务作为行、其小任务横向排在右侧，每个大任务的进展一目了然 | 用户无需滚动/翻页即可在当前视口看到全部大任务及其小任务布局 |
| G2 | **时间线驱动今日聚焦**：覆盖今天的小任务自动进聚焦，**取消星标主导**，降低"每天手动挑今天做什么"的负担 | 今日聚焦 100% 由时间线覆盖今天算出，不再依赖 `focus` 手动标记 |
| G3 | **每日完成可追溯**：每个时间线内的小任务按天有独立的完成记录，日历可回看任意一天完成了哪些 | 任意日期均能查到当日完成的小任务列表；完成记录按「小任务+日期」唯一 |

三个目标正交：G1 管**结构呈现**，G2 管**当下推进**，G3 管**历史追溯**。

## 3. 用户故事（User Stories）

| # | 用户故事 |
|---|---|
| US1 | As a 想系统推进一件大事的用户，I want 大任务一行展示、小任务横向排在其右侧，so that 我一眼就能看清每个大任务下都有哪些小任务、推进到了哪。 |
| US2 | As a 每天执行的用户，I want 时间线覆盖今天的小任务自动进今日聚焦，so that 我每天打开就知道今天该推进哪几件，不用自己挑。 |
| US3 | As a 想持续打卡的用户，I want 在今日聚焦里直接点「完成」按钮把今天这次打卡记下来，so that 我能按天积累、不中断。 |
| US4 | As a 想回看的用户，I want 点日历上的某一天就能看到当天完成的所有任务，so that 我能复盘"那天我做了什么"。 |
| US5 | As a 老用户，I want 我以前记的大任务、小任务（没有起止日期的）打开新版仍原样在、不丢不乱，so that 升级没有数据焦虑。 |

### 5.2 关键交互规格

| 元素 | 规格 |
|---|---|
| **① 今日聚焦横条**（T-03/04/05） | 数据源 = 全部 `startDate<=today<=endDate` 的未软删 note；每行 = 任务名（左）+「完成」按钮（右）；**不显示截止日/倒数**；当日已完成（T-06 有记录）显打勾态。完成按钮交互暂定"点击=标记今天这次完成"，**交互细节待细化（T-14）** |
| **② 矩阵行**（T-01） | 左侧固定列宽显示大任务标题（emoji+名，沿用现有 direction 数据）；右侧为横向滚动容器，内放该 `dir` 下的小任务卡片。`📥未归类` 行承载 `dir===null` 或"无时间线"的兜底任务（T-11/T-17） |
| **② 小任务卡片** | 显示：标题 + 日期显示切换控件（T-10：无截止日期 / 倒数"剩 N 天"）+ 完成态（时间线内今日是否已打卡）。卡片点击进编辑页（T-02 设起止日期）。沿用现有 `.kanban-card` 视觉语言改造，不新建 CSS 框架 |
| **③ 日历**（T-07/08） | 默认月视图；已完成日期（T-06 有记录）打勾/高亮；点击某日 → 切换/下钻到"当天完成列表"视图（列出该日所有完成的小任务名），提供返回。月/周切换属 P2（T-15） |
| **④ 每日复盘**（不改） | 现有"时间账本联动的每日复盘"保持不变，置于日历下方，作为本模块的第三段。详见 §5.3 共处说明 |

### 5.3 与「行动系统」页（含时间账本联动每日复盘）如何共处

- **三段纵向排布**：今日聚焦（当下推进）→ 矩阵区（结构呈现）→ 日历（历史回看）→ 每日复盘（时间账本联动，本次不改）。与现有"今日聚焦 → 我的目标(看板) → 每日复盘"的页面骨架完全一致，只把中段"看板"替换为"矩阵 + 日历"。
- **三轴语义不变**（沿用 `prd-todo-goals.md` §6.3）：今日聚焦=时间轴·当下；矩阵=结构轴；每日复盘=时间轴·回看（联动时间账本）。本次只是把"当下"的筛选逻辑从星标改为时间线，并新增"按天完成 + 日历回看"作为回看轴的增强。
- **每日复盘与完成记录的关系**：本次新增的"每日完成"记录（T-06）与每日复盘（时间账本投入）是两条独立数据轴，是否互相计入见待确认 Q4。

## 6. 数据模型影响初判（Data Model Impact，留给架构师定最终方案）

> 关键约束（来自 `prd-todo-goals.md` §4.1，本次同样适用）：同步 payload 顶层键在 **三处** 被硬编码白名单控制——`supabase_store.py` `RECORD_KEYS`、`server.py` `api_push` SQLite 分支、`server.py` `api_pull` 空 payload 默认值。漏改任一处 → 该键数据跨端**静默丢弃**；改 `server.py` 须**重启后端**才生效。

### 6.1 `notes` 新增字段（安全，无需改后端）

`notes` 记录当前字段：`id, title, body, prio, dueDate, done, doneAt, fav, ord, created, updatedAt, deleted, deviceId, dir, cat, eta, status(todo/doing/done), focus`。

- **新增 `startDate` / `endDate`**（或 `timeline:{start,end}`，`YYYY-MM-DD | null`）：存放小任务时间线。
- **安全性**：`merge_records` 按 `id` 整条记录 LWW 覆盖，新字段随记录整体透传，**不需要任何后端改动**，与"新增顶层数组键"是两回事。架构师可定最终命名（`startDate/endDate` 还是嵌套 `timeline`）。

### 6.2 完成记录存储（核心决策点，两种方案）

| 方案 | 存法 | 后端改动 | PM 倾向 |
|---|---|---|---|
| **B1（推荐）嵌套进 `notes`** | 在 note 上增加 `completions: ["2026-08-03","2026-08-04",…]`（已完成日期数组，按「noteId+date」天然唯一） | **零改动**（随 note 记录同步） | **推荐。** 复用现有 `notes` 同步键，规避"新增顶层键"三处改动 + 重启后端 + 静默丢数据风险（同 `prd-todo-goals.md` A1 哲学） |
| **B2 新增顶层键 `taskCompletions`** | 顶层数组 `[{noteId, date}, …]` | 须改 3 处白名单 + 用户重启后端 + 考虑迁移 | 仅当架构师认为"完成记录应从 note 解耦独立查询"时才采用，代价见上 |

> 无论 B1/B2，完成记录查询语义均为「按 noteId + date 唯一」，支持 T-05 去重与 T-08「某日完成列表」。最终方案由架构师定。

### 6.3 红线与兼容

- **`directions` / `notes` 的 `dir` 外键关系保持不变**：矩阵行=大任务、行内卡片=该 `dir` 下的 note，渲染逻辑完全基于现有 `notes.dir → directions.id`。
- **旧数据兼容**：旧 `notes` 无起止日期 → 默认"无时间线"，按 T-11 兜底（默认不进时间线聚焦）；旧 `focus` 星标保留，仅不再是今日聚焦**唯一**来源（T-11 兜底仍可用）。
- **不执行一次性数据转换脚本、不删除/重命名字段**。最坏回滚 = 换回旧 `workbench.html`，数据无损。
